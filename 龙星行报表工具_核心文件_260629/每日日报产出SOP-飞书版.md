## 二、使用方式：命令行交互

如果你已经熟悉终端，或者需要更可控地执行每一步，可以进入项目目录直接使用命令行交互的方式。

### 1\. 环境安装

在命令行中执行以下指令来进行依赖环境安装：

```Bash
pip install -r requirements.txt
```



### 2\. 爬取每日龙星行的线索和话单数据，并产出日报

```Bash
python main.py
```

作用：

- 爬取龙星行门店原始数据

- 生成 `data/{YYMMDD}/每日报告`，其中`{YYMMDD}`表示当天日期，下同

- 生成 `data/{YYMMDD}/汇总表`

- 自动检查“长沙”是否缺话单或缺日报；如缺，会自动补爬一次

    > 备注：“长沙龙星行”作为脚本中首个进行数据爬取的门店，时常遇到首次爬取失败需重试的情况，原因不明，但不总体影响日报产出
    > 
    > 

**爬取中断了或只有部分门店有产出（例如长沙龙星行的原始数据缺失）怎么办？**

处理方式：

- 直接重跑同一条命令

- 这套流程支持“已有原始文件则跳过”，通常不会重复下载已完成部分



### 3\. 爬取每日建银的线索和话单数据，并产出日报

```Bash
python run_jianyin_stores.py
```

作用：

- 爬取建银 5 店数据

- 生成 `建银门店日报/{YYMMDD}/每日报告`

- 生成 `建银门店日报/{YYMMDD}/汇总表`

建银 5 店包括：

- 售后银马

- 武汉骏马店

- 林肯美诚售后

- 合肥建银马自达店

- 天翔林肯店



### 4\. 生成建银近三天趋势反馈

```Bash
python tools/jianyin_trend_summary.py --date $(date +%y%m%d)
```

作用：

- 汇总建银 5 店今日指标

- 输出近三天趋势

- 适合直接复制到群里或日报汇总里



### 5\. 补跑指定日期

`main.py`、`run_jianyin_stores.py` 和 `tools/recorder.py` 都支持通过环境变量 `REPORT_DATE` 指定目标日期。

#### 补跑龙星行某天（以补跑 6 月 28 日为例，下同）

```Bash
REPORT_DATE=260628 python main.py
```



#### 补跑建银某天

```Bash
REPORT_DATE=260628 python run_jianyin_stores.py
```



#### 生成指定日期建银趋势

```Bash
python tools/jianyin_trend_summary.py --date 260628
```



### 6\. 已有原始文件时，只重生成日报

如果原始 Excel 已经存在，不想重新爬取，可以直接跑处理脚本。单店日报生成示例如下：

```Bash
python tools/process_clue_report.py \
  --call_file data/260628/原始数据/长沙-aicc-话单-260629.xlsx \
  --xiansuo_file data/260628/原始数据/长沙-outcall-线索明细-260629.xlsx \
  --company 长沙 \
  --date 260628 \
  --output_dir data/260628/
```



### 7\. 新增或修改门店配置

门店配置主要维护在两个地方：

- 龙星行体系：`tools/recorder.py` 里的 `ACCOUNTS`

- 建银体系：`run_jianyin_stores.py` 里的账号列表

#### 7\.1 最基础的门店配置

最小配置长这样：

```Python
{
    "name": "门店名",
    "username": "账号",
    "password": "密码",
}
```

各字段作用：

- `name`

    - 门店名称

    - 同时用于原始文件命名、日报命名、汇总表命名的默认前缀

- `username`

    - 登录外呼/话单系统的账号

- `password`

    - 登录密码



#### 7\.2 分机器人门店配置

如果一个租户里有多个机器人，需要在基础配置上继续补这些字段：

```Python
{
    "name": "海珠龙星行",
    "username": "guangzhouhaizhu1234",
    "password": "gzhz123456",
    "group_by_call_field": "机器人",
    "required_group_values": [
        "龙星行-新车首呼-广东广州海珠",
        "龙星行-新车首呼-广东广州番禺",
    ],
    "group_display_names": {
        "龙星行-新车首呼-广东广州海珠": "广州龙星行-海珠新车首呼",
        "龙星行-新车首呼-广东广州番禺": "广州龙星行-番禺新车首呼",
    },
    "group_summary_names": {
        "龙星行-新车首呼-广东广州海珠": "海珠新车首呼",
        "龙星行-新车首呼-广东广州番禺": "番禺新车首呼",
    },
}
```

这些字段分别表示：

- `group_by_call_field`

    - 按话单表里的哪个字段拆分统计

    - 目前多机器人门店通常写 `机器人`

- `required_group_values`

    - 强制保留的分组值列表

    - 即使某天某个机器人没有新增线索，只要 MTD 或历史上需要保留，也会继续出对应列/对应文件

    - 这里填的是**话单表原始值**

- `group_display_names`

    - 分组后的**日报名称映射**

    - 键：话单表里的原始机器人名

    - 值：你希望日报里展示/输出的名称

    - 例如：

        - 原始值：`龙星行-新车首呼-广西南宁`

        - 日报名：`广西龙星行-南宁新车首呼`

- `group_summary_names`

    - 分组后的**\*\*汇总表名称映射\*\***

    - 键：话单表里的原始机器人名

    - 值：你希望汇总表文件名、表头里显示的名称

    - 如果不写，默认会沿用 `group_display_names`



#### 7\.3 合并汇总表配置

如果一个租户的多个机器人要合并成**一张汇总表**，再补这个字段：

```Python
"merge_summary_title": "广州新车"
```

作用：

- 不再输出多个单独汇总表

- 改为输出一张合并汇总表

- 文件名会变成：

```Plain Text
广州新车_日度月度汇总表_YYMMDD.xlsx
```

如果**\*\*不写\*\*** \`merge\_summary\_title\`：

- 每个机器人各出一份汇总表



#### 7\.4 MTD 起始日期配置

如果门店不是从月初开始上线，或者本月中途切换口径，需要补：

```Python
"mtd_start_date": "260603"
```

作用：

- 指定 MTD 从哪一天开始算

- 格式固定为 `YYMMDD`



#### 7\.5 广州售后类特殊配置

如果门店需要在处理前剔除特定线索，再补：

```Python
"exclude_clue_ids": [
    "2056196796951138305",
    "2056196098764095489",
]
```

作用：

- 在匹配和统计前先剔除这些线索 ID



#### 7\.6 修改门店配置时的判断顺序

建议按这个顺序判断：

1. 这是龙星行还是建银门店？

2. 是单机器人还是多机器人？

3. 日报名称和汇总表名称是否一致？

4. 汇总表是分开还是合并？

5. MTD 是否从月初开始？

6. 是否需要剔除特殊线索？



#### 7\.7 改完配置后怎么验证

最少要检查这几件事：

1. 原始文件是否成功落地

2. 每日报告文件名是否符合预期

3. 汇总表文件名是否符合预期

4. 如果是合并汇总表，表头列名是否正确

5. 如果配置了 `mtd_start_date`，MTD 是否按预期起算

## 三、数据日报产出的业务逻辑

这一部分主要对应 `tools/process_clue_report.py` 的处理逻辑。可以把它理解成一句话：

- *先把当天导出的线索表和话单表清洗干净，再按线索 ID 匹配，最后生成日报文本和汇总表所需的当日统计结果。*

### 2\. 原始数据来自哪里

龙星行和建银体系每天都会先下载两类 Excel：

- 龙星行线索表：`data/YYMMDD/原始数据/{门店}-outcall-线索明细-{抓取日}.xlsx`

- 龙星行话单表：`data/YYMMDD/原始数据/{门店}-aicc-话单-{抓取日}.xlsx`

- 建银线索表：`建银门店日报/YYMMDD/原始数据/{门店}-outcall-线索明细-{抓取日}.xlsx`

- 建银话单表：`建银门店日报/YYMMDD/原始数据/{门店}-aicc-话单-{抓取日}.xlsx`

其中：

- 线索表用于看新增线索、接通状态、意向等级、线索状态等

- 话单表用于看呼叫通次、机器人分组、通话状态详情、通话时长等

关于数据时间范围：

- 线索表和话单表中的数据时间范围默认为当月第一天至今

- 若有门店是当月新增且配置了`mtd_start_date`，则时间范围为`mtd_start_date` 至今



### 3\. 日报的基础处理顺序

日报生成时，整体按下面顺序处理：

1. 读取线索表和话单表

2. 统一把日期字段转成 `YYMMDD`

3. 按目标日期筛出“当天新增线索”和“当天话单”

4. 对话单按线索 ID 与线索表做匹配（同一个线索 ID 仅保留匹配到的第一条话单，即保留线索终态）

5. 必要时按配置剔除特殊线索

6. 如果门店配置了多机器人，就先按话单里的 `机器人` 字段拆组

7. 对每个门店或每个机器人分别生成日报文本

8. 同时把日报统计结果传给汇总表逻辑



### 4\. 日报里各项数据怎么来的

|字段|来源|口径|备注|
|---|---|---|---|
|新增线索量|当天线索表|`线索下发时间 == 目标日期`||
|接通线索|当天新增线索与话单匹配后的结果|`通话状态` 含 `已接通`||
|未接通线索|当天新增线索与话单匹配后的结果|没有进入“已接通”的新增线索||
|未接通原因 TOP3|匹配后的未接通线索|沿用当前代码里的未接通原因归类规则|特殊门店如果有独立口径，会在门店专用逻辑里单独处理|
|线索重呼情况|当天话单表中未与线索表匹配的部分|||

## 四、汇总表的数据来源

这一部分主要对应 `tools/daily_summary.py`。汇总表分成两个板块：

- MTD（本月至今）

- Daily Report（当日）

![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=MGU3ODFhZDRhOTg4NWYwYjJkZTNiMjE5Yjc5NDJiZTNfMjE5MDg2ZGI4M2ExMTA1ZTcxZGU1NzI5ZjEzZTEyZDdfSUQ6NzY1NjcyOTQ4Mjk1MTEwMTY3N18xNzgyNzIyNDc4OjE3ODI4MDg4NzhfVjM)

### 1\. MTD 板块的数据来源

MTD 不是靠每天累加 Excel 算出来的，而是直接基于“当次下载的整月原始数据”按目标日期回切。

|汇总表字段|数据来源|核心口径|备注|
|---|---|---|---|
|累计线索量|当日下载的整月线索表|`线索下发时间 <= 目标日期`|如配置了 `mtd_start_date`，则同时要求 `线索下发时间 >= MTD 起始日期`|
|接通量|当日下载的整月线索表|MTD 范围内 `通话状态` 含 `已接通`|使用线索表里的最新通话状态|
|有效线索量|当日下载的整月线索表|MTD 范围内满足“有效线索”口径的线索数|当前代码按 `线索状态` 包含 `有效` 统计|
|呼叫通次|当日下载的整月话单表|`结束时间 <= 目标日期`|如配置了 `mtd_start_date`，则同时要求 `结束时间 >= MTD 起始日期`|
|平均呼叫通次|汇总表计算|`呼叫通次 / 累计线索量`|分母为 0 时显示 0|
|接通率|汇总表计算|`接通量 / 累计线索量`|百分比格式|
|接通有效率|汇总表计算|`有效线索量 / 接通量`|百分比格式|
|整体有效率|汇总表计算|`有效线索量 / 累计线索量`|百分比格式|

### 2\. Daily Report 板块的数据来源



日报部分的数据，核心来自“当天统计结果 \+ 前一天 tracking（本地存储的历史数据）”。

|汇总表字段|数据来源|核心口径|备注|
|---|---|---|---|
|新增线索量|当天线索表|`线索下发时间 == 目标日期`|对多机器人门店，会先按话单匹配到的机器人拆分|
|昨日全天对比（新增线索量）|tracking|前一天记录的 `新增线索量`|文件在 `_tracking/{YYMM}/{门店或机器人}.json`|
|新增线索接通量|当天线索表 \+ 去重后话单表|当天新增线索中，匹配到话单且 `通话状态` 含 `已接通` 的数量|话单匹配时同一线索 ID 保留 `结束时间` 最新的一通（终态）|
|新增线索呼叫通次|当天原始话单表|`结束时间 == 目标日期`，**且线索 ID 属于当天新增线索的话单行数**|不去重，一通电话算一行|
|已接通通话平均时长（向上取整）|当天原始话单表<br>|当天新增线索相关话单中，`通话状态` 含 `已接通` 的平均通话时长|按分钟向上取整；无数据时为 0|
|平均呼叫通次|汇总表计算|`新增线索呼叫通次 / 新增线索量`|分母为 0 时显示 0|
|接通率|汇总表计算|`新增线索接通量 / 新增线索量`|多机器人合并表中字段名会带公式备注|
|昨日全天对比（接通率）|tracking|前一天的 `新增线索接通量 / 新增线索量`|读取前一天分子分母后重新计算，不直接抄历史百分比|
|接通有效率|汇总表计算|`有效线索量 / 新增线索接通量`|多机器人合并表中字段名会带公式备注|
|整体有效率|汇总表计算|`有效线索量 / 新增线索量`|多机器人合并表中字段名会带公式备注|
|昨日全天对比（整体有效率）|tracking|前一天的 `有效线索量 / 新增线索量`|读取前一天分子分母后重新计算|

昨日对比不是直接抄前一天的百分比，而是先取前一天记录的原始数量，再按当前口径重新计算比率。这样可以避免历史版本口径调整后出现对比失真。



### 3\. tracking 文件现在怎么存

当前 tracking 已经按月份分目录保存：

- 龙星行示例：`_tracking/2606/长沙.json`

- 多机器人示例：`_tracking/2606/广州龙星行-海珠新车首呼.json`

|tracking 字段|写入来源|主要用途|
|---|---|---|
|呼叫通次|当天报表处理结果|作为后续昨日对比和补算基础数据|
|新增线索量|当天报表处理结果|计算昨日新增线索量、昨日接通率、昨日整体有效率|
|新增线索接通量|当天报表处理结果|计算昨日接通率|
|有效线索量|当天报表处理结果|计算昨日接通有效率、昨日整体有效率|
|已接通通话平均时长分钟|当天报表处理结果|给特殊门店保留“已接通通话平均时长（向上取整）”历史值|



### 4\. 月初为什么要查上月最后一天

现在月初第一天的汇总表，已经支持先检查“上月最后一天是否有 tracking 数据”：

- 如果有，就补到本月第一天汇总表的昨日对比里

- 如果没有，就保持为空

这样可以避免每月 1 号的日报汇总表缺少“昨日”参考值。
