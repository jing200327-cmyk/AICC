# 日度月度汇总表数据计算说明

## 数据来源总览

| 数据 | 来源文件 | 说明 |
|------|---------|------|
| 全月线索明细 | 当日下载的 `data/{date}/原始数据/{公司}-outcall-线索明细-{date}.xlsx` | 按 `COMPLETED`、`RECALL`、`PENDING` 三种平台线索状态分别导出后按线索 ID 合并；分组账户只为可能无话单的 `PENDING` 线索额外导出机器人映射 |
| 当日话单 | 当日下载的 `data/{date}/原始数据/{公司}-aicc-话单-{date}.xlsx` | 爬虫设置时间范围为当月初至当天，包含全月话单 |
| tracking | `_tracking/{YYMM}/{公司或机器人}.json` | 每次跑日报时同时记录 Daily 指标和 `MTD累计线索量/接通量/有效线索量/呼叫通次` 完整快照 |

## 字段定义与计算逻辑

### MTD 板块（月至今累计）

| 字段 | 数据来源 | 计算方式 |
|------|---------|---------|
| 累计线索量 | 目标日 tracking 快照 | 月初至 date 的唯一线索 ID 数 |
| 接通量 | 目标日 tracking 快照 | 月初至 date 线索表终态为已接通的线索数 |
| 有效线索量 | 目标日 tracking 快照 | 月初至 date 线索表终态为有效的线索数 |
| 呼叫通次 | 目标日 tracking 快照 | 月初至 date 的全部话单行数 |
| 平均呼叫通次 | — | 呼叫通次 ÷ 累计线索量 |
| 接通率 | — | 接通量 ÷ 累计线索量 |
| 接通有效率 | — | 有效线索量 ÷ 接通量 |
| 整体有效率 | — | 有效线索量 ÷ 累计线索量 |

> **说明**：Daily 接通量只反映“当日新增线索在当日最后一通是否接通”；MTD 接通量还必须包含后续日期才接通的历史线索，因此不能累加 Daily 接通量。每个报表日均基于完整月初至当日原始数据生成 MTD 快照并写入 tracking。
>
> tracking 缺失日期时，先读取 `data/{date}/汇总表` 或区间目录中保存的同日汇总表，按机器人列恢复完整 Daily 记录。若连续缺失日没有单日文件，但后续已有 MTD 汇总快照，只保存带 `source`、`source_mtd_date` 和 `covered_dates` 的 `_mtd_backfill` 区间差额；该差额仅用于 MTD，不伪造各天 Daily。没有可靠来源的缺口保持告警状态。

### Daily Report 板块（当日详情）

| 字段 | 数据来源 | 计算方式 |
|------|---------|---------|
| 新增线索量 | 线索明细 | 线索下发时间等于目标日期的唯一线索ID数；历史/重呼线索不计入 |
| 昨日全天对比 | `_tracking/` JSON | 取 tracking 中**前一天**记录的 `新增线索量` |
| 新增线索接通量 | 每日日报 | 当日新增线索集合中，取每个线索当天最后一通话单，且通话状态含“已接通”的线索数 |
| 未接通线索 | 每日日报 | 当天新增线索中未进入“已接通”的线索；没有匹配到任何当天话单的线索也计入，并归类为“无话单/未外呼” |
| 新增线索呼叫通次 | 原始话单表 | 当日话单按结束时间等于当天筛选后，再限定线索ID属于当日新增线索集合的总行数；话单行不去重 |
| 平均呼叫通次 | — | 新增线索呼叫通次 ÷ 新增线索量 |
| 接通率 | — | 新增线索接通量 ÷ 新增线索量 |
| 昨日全天对比（接通率） | `_tracking/` JSON | 用前一天记录的 `新增线索接通量 / 新增线索量` 重算 |
| 接通有效率 | — | 有效线索量 ÷ 新增线索接通量 |
| 整体有效率 | — | 有效线索量 ÷ 新增线索量 |
| 昨日全天对比（整体有效率） | `_tracking/` JSON | 用前一天记录的 `有效线索量 / 新增线索量` 重算 |

> **说明**：昨日对比数据不是直接从 tracking 取原值，而是取前一天的分子/分母后重算比率，确保对比口径一致。

> **重复话单与分组说明**：当日原始话单不去重，用于“新增线索呼叫通次”；唯一线索指标按线索 ID 去重并保留当天最后一通。所有重复线索的完整话单另存为 `中间文件/{公司}_重复线索话单.xlsx`。分组账户优先使用当天话单的机器人，未匹配时再使用线索表中的 `PENDING` 映射和历史话单映射；单机器人门店可将仍无映射的线索归入唯一机器人，多机器人门店保留为“未匹配机器人”并提示数据不完整。

> **下载时间口径**：平台线索明细接口的 `startTime`、`endTime` 筛选的是“外呼时间”，不是“线索下发时间”。日报下载不使用该时间窗口，而是分页读取各 `clueFlowType` 的完整明细，再按 `线索下发时间` 在本地筛选目标区间，避免漏掉外呼时间不在窗口内的已完成线索。

## 数据流转路径

### 爬取阶段（recorder.py）

```
外呼系统(outcall-manage)
  → 登录 → 设置线索开始日期为本月初
  → 按 COMPLETED / RECALL / PENDING 分别导出
  → 分组账户仅为 PENDING 线索按机器人补充归属映射
  → 保存到 data/{date}/原始数据/{公司}-outcall-线索明细-{date}.xlsx

呼叫系统(aicc-poc)
  → 登录 → 设置话单开始时间为本月初 → 查询 → 导出话单
  → 保存到 data/{date}/原始数据/{公司}-aicc-话单-{date}.xlsx
```

### 处理阶段（process_clue_report.py → daily_summary.py）

```
读入话单文件 → 按 结束时间==当天 筛选 → 去重后关联当日新增线索
读入线索文件 → 按 线索下发时间==当天 取得唯一新增线索ID
               → 新增呼叫通次 = 当天原始话单中属于上述新增ID的行数
               → 其余当天话单归入历史/重呼补充明细
               → 机器人分组及“总量=纳入+明确排除+未匹配”校验 → 生成日报文本

调用 generate_daily_summary():
  1. 读取 `_tracking/{YYMM}/{公司或机器人}.json`
  2. 写入当天记录（呼叫通次 + 日报数据）
  3. 从已有单日汇总表回填缺失 tracking；必要时保存有来源的 MTD 区间差额
  4. MTD = tracking 中目标日期的 `MTD累计*` 完整快照；旧记录无快照时兼容 Daily 累加与区间差额
  5. 昨日对比 = tracking 中前一天记录
  6. 生成 Excel
```

## Excel 输出模板

`data/{date}/汇总表/{公司}_日度月度汇总表_{date}.xlsx`

表结构：
- 第1行：表头（蓝色底 #4E83FD）— 业务场景 / 单位 / {公司名}
- MTD 板块：规模指标 + 检测指标
- Daily Report 板块：规模指标 + 检测指标 + 昨日全天对比
